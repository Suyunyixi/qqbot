# 核心对话审查

## 已定位并修正

- 已保存的图片在较长间隔后的追问中没有进入模型；现有图片话题可跨时间继续，旧图可通过历史图片工具按会话查找、读取。QQ 原始记录和附件归档独立于工作区。
- 仅凭当前消息无图片或工作区为空，不能推断历史图片没送到；模型可以核验图片的归档状态和读取结果。
- 引用旧消息图片时，优先使用明确引用的消息，避免误选附近新图。仅在平台提供的引用标识与本地消息标识对应时自动定位，否则仍可按历史查找。
- 机器人自己发出的图片可能没有网络地址，应从会话工作区的附件记录读取。
- 群友发言可能和图片共同构成上下文；图片不可读不意味着其他原话不存在。
- 图片参与回答时，纯文字语义复核器看不到图片，可能错误否定回答；这类回合不执行该复核。
- 用户先分段说话、隔较久只发送 @ 时，提取发起人此前发言不能只依赖近期时间窗口；仍保留时间供模型判断相关性。
- 用户消息在上一轮处理期间排队时，上一轮之后发出的机器人回复此前不在下一轮上下文中；现单独标明发生顺序。
- 历史文字搜索此前只返回最近 20 条匹配，无法继续查更早结果；现可传入序号分页。
- 单条超长消息此前只将开头送去摘要却推进了整条消息的位置；现在按段连续整理，所有段成功后才推进。失败时保留原有进度和原始消息。
- 仅因“最新”等词就强制联网可能误伤“刚才那张最新图片”；已移除基于关键词的联网拦截，由模型结合请求判断和使用搜索工具。

## 仍需注意的实际边界

- 最近消息和摘要在每轮输入中仍有数量及字符预算；更早内容需要模型选择历史搜索或图片回查工具，不保证模型每次都能主动找到。文字搜索目前是关键词子串匹配，不是语义检索。
- 群聊消息只记录平台实际推送的内容；机器人无法恢复平台从未推送、文件未归档且原地址已失效的附件。
- 历史图片读取需要当前模型支持图片输入。图片超过现有 10 MB 输入限制时会明确失败，不代表记录被删除。
- 普通消息在当前回合处理期间会被追加文字和附件信息；运行中的图片不会自动嵌入模型，模型可以使用历史图片工具回查。
- 语义复核只是一次可关闭的模型检查，对纯文字也可能判断失误；它不是正确性的证明。
- 单条超长消息会分多次模型调用进行摘要，只有全部成功才提交进度；中途失败后重试会重新处理已成功的部分，可能产生额外费用。
- 测试验证输入、工具调用和状态流转，不能保证真实模型每次都正确理解、选择工具或使用符合人格的措辞。

## 2026-11-06 引用与历史读取审查

- QQ 消息里的引用原文先前只在触发消息本身被解析；普通群友的消息虽然保存了原始事件，最近聊天、实时插话、记忆整理和复核却漏掉引用。现在通过同一消息视图读取正文、引用、附件和消息标识。
- 原先历史搜索、分页翻阅和单条读取没有完整返回引用，关键词也无法命中引用文字；现已补全，聊天记录管理页同样可展示并搜索引用。
- 最近聊天过去固定只取 16,000 字符，而且普通消息没有回查标识；现在按模型上下文配置估算输入预算，按消息边界保留，超长内容保留标识供回查。字符预算只是估算，不是精确 token 计数。
- 已开启语义复核时，以前调用历史工具后就跳过复核；现在仅调用只读工具的回合也允许复核话题关联。模型可能额外调用一次，带来延迟与 token 消耗；复核器不看图片，不能验证图片内容。
- 实际模型模拟中，原始引用补齐后曾两次把无关旧图混进回答；加入通用话题理解与只读查询后的复核后，一次模拟回答聚焦引用，但仍调用了旧图工具。不能据此保证以后不会误判或产生额外调用。
- 最近消息条数、摘要和长期记忆仍有输入预算；更早消息需模型通过历史工具翻阅或关键词搜索，目前没有语义检索，模型也可能没有主动回查。默认自动载入的图片数量仍有限制，其他图片需模型读取。QQ 没提供原引用作者、原消息或文件时无法自行还原。

## 持续会话调整

- 不再每轮清空 Agent 消息或重置摘要截断位置；同一会话通过 LangGraph 检查点持续运行，历史压缩交由 Deep Agents。原始 QQ 记录仍独立保存在 SQLite。
- 普通消息仍先记录且不调用模型；触发时增量补入自上次记录位置以来的群消息。既有检查点第一次升级时会附带最近的原始聊天，原检查点和原始记录均不删除。
- 去除了额外语义复核、人工工具调用次数限制和群聊插话阻断发送；保留 LangGraph 的递归上限、平台交付错误和原始记录。
- 上面关于“语义复核”的条目记录的是之前实现，不代表当前运行流程。
